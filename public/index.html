API de ventas

Consulta el consolidado de ventas por sucursal y año, o registra una nueva venta. Esta referencia describe las rutas disponibles y los formatos que espera el servicio.

URL base local http://localhost:3000
JSON · Sin autenticación

Referencia

Endpoints

La API está versionada bajo /api/v1. En producción, reemplaza el host local por el dominio donde esté desplegado el servicio.

GET/api/v1/ventas/consolidado

Obtiene el consolidado de ventas para una sucursal y un año.

POST/api/v1/ventas

Registra una venta con producto, cliente, cantidad y fecha.

Consulta de datos

Consultar consolidado

GET/api/v1/ventas/consolidado

Envía ambos parámetros como query string. El servicio ejecuta el procedimiento almacenado de consolidación y devuelve sus filas.

ParámetroTipo esperadoRequeridoDescripción
sucursalTexto o númeroSíIdentificador de la sucursal.
anioNúmeroSíAño para el que se solicita el consolidado.
Ejemplo de solicitud
curl "http://localhost:3000/api/v1/ventas/consolidado?sucursal=1&anio=2025"
Respuesta · 200 OK
{
  "status": "success",
  "total_registros": 2,
  "data": [
    { "...": "Las columnas dependen del procedimiento de base de datos" },
    { "...": "..." }
  ]
}

Escritura de datos

Registrar una venta

POST/api/v1/ventas

Envía un objeto JSON con todos los campos requeridos. El servidor ejecuta el procedimiento almacenado de registro y responde con los datos recibidos.

CampoTipo esperadoRequeridoDescripción
id_productoNúmero o textoSíIdentificador del producto.
id_clienteNúmero o textoSíIdentificador del cliente.
cantidadNúmeroSíCantidad vendida. Debe ser un valor distinto de cero.
fecha_ventaTextoSíFecha compatible con la columna correspondiente en MySQL.
Ejemplo de solicitud
curl -X POST "http://localhost:3000/api/v1/ventas" ^
  -H "Content-Type: application/json" ^
  -d "{\"id_producto\":12,\"id_cliente\":34,\"cantidad\":2,\"fecha_venta\":\"2025-05-20\"}"
Respuesta · 201 Created
{
  "status": "success",
  "message": "Venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 12,
    "id_cliente": 34,
    "cantidad": 2,
    "fecha_venta": "2025-05-20"
  }
}
El servidor requiere Content-Type: application/json. Los campos se envían al procedimiento de MySQL; el formato y las reglas adicionales de fecha, identificadores y cantidad dependen de la base de datos.

Protocolo

Respuestas y errores

400 · Solicitud inválida

El consolidado requiere sucursal y anio. Para registrar, todos los campos del cuerpo deben estar presentes y tener un valor distinto de cero/vacío.

GET · Faltan parámetros
{
  "error": "Bad Request",
  "message": "Debe Enviar Ambos Parametros"
}
POST · Faltan campos
{
  "error": "Bad request",
  "message": "Todos los campos son obligatorios"
}

500 · Error del servidor

La consulta o el registro encontró un error en MySQL. Revisa la disponibilidad de la base de datos y los valores enviados.

GET · Error de consulta
{
  "error": "Internal Server Error",
  "message": "Error En MySQL"
}
POST · Error de registro
{
  "error": "Internal Server Error",
  "message": "Error al registrar la venta en la base de datos"
}
La API recibe JSON y responde con JSON. El puerto predeterminado es 3000; puede cambiarse mediante la variable de entorno PORT.
